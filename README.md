# ИСВО — Hero главной страницы

Отдельная рабочая основа сайта в `Code/isvo-site`. Реализованы только Hero,
боковая навигация, мобильная шапка и окно контактов. Три предыдущих прототипа
в `Code/ISVO Website Redesign*` не изменены.

Стек: **Astro 7.3.5, TypeScript 5.9.3, Tailwind CSS 4.3.3**, Vite внутри Astro.
Основа взята из локального проекта «Фотограф Тюркан-Мария»: структура `app/`,
файловая маршрутизация и статическая сборка. Вся разметка генерируется в HTML;
меню и нативные диалоги управляются небольшим TypeScript-скриптом. React и его
гидратация удалены: для текущего интерфейса они не нужны. Framer Motion также
не используется. На хостинге достаточно раздавать `dist/`.

## Запуск

Из папки `Code/isvo-site` сайт запускается через `Makefile`, как в проекте
«Фотограф Тюркан-Мария»:

```sh
make
```

`make` (или `make dev`) устанавливает зависимости, если отсутствует
`node_modules`, и запускает сайт на http://127.0.0.1:4321/.
Если порт занят, Astro выбирает следующий свободный и выводит адрес в терминале.
При наличии встроенного Node.js Codex используется он; иначе — Node.js из `PATH`.
Перед запуском проверяется минимальная версия Node.js 22.19.0 (нужна Lighthouse).

Команды из `Code/isvo-site`:

| Команда | Действие |
| --- | --- |
| `make install` | Установка зависимостей через `npm ci --include=dev` |
| `make check` | Проверка Astro и TypeScript |
| `make build` | Статическая сборка в `dist/` |
| `make preview` | Просмотр готовой сборки |
| `make audit` | Сборка и мобильный Lighthouse; нужен установленный Chrome/Chromium |
| `make audit-desktop` | Сборка и десктопный Lighthouse |
| `make release` | Чистая установка зависимостей, проверка и сборка; без публикации |

Прямой запуск из `Code/isvo-site` через npm также доступен.
Нужен Node.js **22.19+**. В `.nvmrc` указан 22.22.0.

```sh
nvm use
npm ci
npm run dev
```

Адрес: http://127.0.0.1:4321/.

```sh
npm run check
npm run build
npm run preview
```

## Фотография и референс

Использована реальная фотография из материалов ИСВО:
`Каталог/Уборка урожая/Навесной овощеуборочный транспортер/НОУТ-5/НОУТ-5_009.JPG`.
Ракурс сверху показывает ленту и раму НОУТ-5 на капустном поле.
Трактор исключён из композиции кадрированием: прямоугольник исходника
`left: 300, top: 100, width: 2700, height: 2025` (4:3).
Оригинал не изменён. В `app/assets/` сохранена кадрированная копия JPEG 2700×2025.
Astro автоматически создаёт AVIF (качество 50) и WebP (качество 76) шириной
480, 800, 1280 и 1920 пикселей. `<picture>` выбирает AVIF при поддержке браузером,
иначе WebP; `srcset` и `sizes` учитывают ширину фотографии и боковой панели.
Готовые изображения получают хеш в имени в `dist/assets/`; исходный JPEG
не загружается браузером. Для замены фотографии достаточно обновить исходник.
Изображение загружается eager с `fetchpriority="high"`, известными размерами,
`object-fit: cover` и фокусом на оборудовании. На десктопе Hero занимает всю
высоту окна (минимум 640 px для размещения текста); на мобильном фотография
располагается после текста и CTA и заполняет оставшуюся высоту. Жёлтая диагональ
над фотографией удалена; короткий акцент у подписи сохранён.

Существующий логотип взят из `Code/Logo/isvo-wordmark.svg`.
Manrope и его OFL-лицензия взяты из локальных материалов проекта «Эльф».
Оба начертания переведены из TTF в WOFF2 без удаления символов: 190 КБ → 61 КБ
(десятичные единицы). Жирное начертание предзагружается; `font-display: swap`
позволяет показывать текст до загрузки шрифта.
Внешних запросов к фотобанкам и сервисам шрифтов нет.

Отдельный скриншот референса не был приложен: композиция реализована по текстовому
ТЗ. Проверка точного совпадения с референсом остаётся невозможной без этого изображения.
Графического placeholder нет — подходящая фотография найдена в материалах проекта.

## Заявка

В старом прототипе форма показывала успех по таймеру без отправки данных.
Здесь все CTA используют один обработчик и событие `isvo:inquiry`.
До подключения формы открывается доступный нативный диалог с телефоном и email.
Никаких данных автоматически не отправляется. Без JavaScript CTA остаются обычными
`mailto:`-ссылками.

Для подключения существующего интерфейса формы:

```ts
document.addEventListener("isvo:inquiry", (event) => {
  event.preventDefault(); // отключить штатное окно контактов
  // Открыть реальную форму, передав event.detail.source и event.detail.intent.
});
```

`detail.intent`: `proposal` или `selection`.
`detail.source`: `hero`, `sidebar`, `navigation` или `hero-selector`.
Для полноценной отправки нужны интерфейс формы и рабочая интеграция с сервером/CRM.
Обработчик ответа должен показывать успех только после подтверждённой отправки.
Секреты интеграции нельзя размещать в статическом клиентском коде.

Телефон `8 800 222-67-11` и email `906711@bk.ru` взяты из предоставленного
скриншота `Перая версия/контакты.png`. Перед публикацией следует подтвердить
их актуальность; при необходимости достаточно изменить `app/content/site.ts`.

## Будущие разделы

«Подобрать технику» прокручивает страницу к `id="equipment-selector"` и переносит
туда фокус. При `prefers-reduced-motion` прокрутка мгновенная. Пока такого блока
нет, открывается то же окно контактов с приглашением подобрать технику.

Пункты «Техника», «О компании» и «Сервис и запчасти» обозначены как «Скоро»
и не являются неработающими ссылками. После создания соответствующих страниц
укажите их адреса в массиве `navigation` и настройте активный пункт для новых маршрутов.
Каталог, карточки продукции, SEO-блоки, footer и другие страницы не реализованы.

## Проверка

Проверки: `npm run check` и `npm run build`.
Браузерная проверка включает 1920×1080, 1440×900, 1024×768, 390×844 и 320×740:
горизонтальную прокрутку, загрузку фотографии, один H1, доступность основной CTA
в первом экране, мобильное меню, Escape, возврат фокуса, отсутствие ошибок,
интеграционное событие, будущий якорь подбора, reduced motion и режим без JavaScript.

Скриншоты и результат локального прогона сохраняются в игнорируемой папке `outputs/`.

## Локальная проверка производительности

```sh
make audit
make audit-desktop
```

Команда пересобирает сайт, поднимает временный сервер на свободном порту только
на `127.0.0.1`, запускает Lighthouse и закрывает сервер. Нужен Chrome/Chromium;
при нестандартном расположении можно задать `CHROME_PATH`. Отчёты HTML и JSON
сохраняются в `outputs/lighthouse-mobile.report.*` или
`outputs/lighthouse-desktop.report.*`. Аудит запускается отдельно от `release`,
чтобы обычная сборка не зависела от установленного браузера.

Это лабораторная оценка готовой страницы, без серверного сжатия и кеширования.
На хостинге остаются Brotli/Gzip, корректные `Content-Type` для AVIF/WOFF2,
политика кеширования и проверка публичного URL в PageSpeed Insights.
Длительное immutable-кеширование подходит для файлов с хешем в `assets/`;
для HTML и файлов без версии в имени нужна политика с обновлением кеша.

Локальный замер 02.11.2026, Lighthouse 13.6.0, мобильный профиль со стандартным
ограничением сети и процессора, без сжатия и HTTP-кеша:

| Показатель | До оптимизации | После |
| --- | --- | --- |
| Performance | 86 | 99 |
| LCP | 4,2 с | 2,0 с |
| Объём переданных ресурсов | 595 КиБ | 168 КиБ |
| JavaScript страницы | ~199 КБ в отдельных файлах | ~1,8 КБ внутри HTML |

Десктопный Performance: 100. Accessibility, Best Practices и SEO: 100 в обоих
профилях. Это отдельные лабораторные прогоны, результаты на публичном сервере
могут отличаться. Проверены шесть размеров экрана (320–1920 px), отсутствие
изменений геометрии, меню, Escape, возврат фокуса, клики вне диалогов,
отмена `isvo:inquiry`, будущий якорь подбора, reduced motion, WebP-fallback
и работа без JavaScript. Результаты и скриншоты: `outputs/performance/`.
